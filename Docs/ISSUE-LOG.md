## What this file is, and what it is not

This is an **index**, not an archive. Every row is a pointer. The full account of any issue already
exists in four permanent places: the issue thread, the pull request body, the commit messages and
the linked branch. Copying that prose here would duplicate it into a fifth place that nothing keeps
current.

What the rest of `Docs/` holds is the *durable lesson*, filed under the topic a future reader would
actually search. Someone asking "how do I run a Linux build locally?" opens `WORKFLOW.md`; they do
not know, and should not need to know, that CI happened to be issue 1. This file exists only to
answer the one question the topic documents scatter: **what has actually been finished, and where
did each one leave its mark.**

Which means the rule for maintaining it is narrow. Add a row when an issue merges, and never write a
paragraph here. If a row wants to grow into an explanation, that explanation belongs in the topic
document and the row should link to it instead.

> **Not to be confused with [`ISSUES.md`](ISSUES.md).** That file is scoped to defects found in the
> test suite itself, and numbers them independently. Its "Issue 1" and "Issue 2" are test-suite
> defects with no relation to GitHub #1 and #2. This file tracks GitHub issue numbers. The
> overlapping names are an accident of the backlog moving into GitHub after `ISSUES.md` already
> existed.

| #1 | [#5](https://github.com/sequeiralabs/foobar/issues/5) | `configureDatabase` discards the diagnostic as well as misclassifying it. `PSQLError` has no `LocalizedError` conformance, so `localizedDescription` yields the `NSError` bridge string. PostgresNIO makes `description` deliberately generic to prevent leaking sensitive data and documents `String(reflecting:)` as the way in, so the detail belongs in a log line and never in a response body. |

SwiftPM only re-emits it when that file recompiles, which is why it is easy to believe it has gone away. Filed 2026-08-16, to be done alongside #36. |
| #1 | [#28](https://github.com/sequeiralabs/foobar/issues/28) | Branch protection is unavailable on private repositories on the Free plan, and both the rulesets and classic protection APIs return 403. | #13 | [#17](https://github.com/sequeiralabs/foobar/issues/17) | **The `409` tests cannot tell which code path produced the conflict.** Deleting the entire pre-check from `updateDepartment` leaves all 21 tests passing, because the unique index then rejects the `save` and the `catch` returns the same `409`. Distinguishing them needs either a rollback counter (the method already used for the constraint-violation work) or different response prose, which would be a behaviour change. |

As in #13, the outcome is pinned but the path to it is not, so a bug there silently degrades a clean pre-check into a failed transaction. |

| #18 | [`TESTING.md`](TESTING.md) | **`.serialized` does not serialize one suite against another.** A second `@Suite` over the same database made both suites fail almost entirely, each one's `autoRevert()` dropping the other's tables mid-test. It surfaces as `relation "departments" does not exist` inside a migration that had just succeeded, so it reads as a broken migration rather than a concurrency fault, and it lands in whichever test happened to be running. Declare new database tests in an extension of the existing suite. |
| #39 | [#60](https://github.com/sequeiralabs/company-directory/issues/60) | **A reference checker needs three verdicts, not two.** A prototype run against `WALKTHROUGH.md` reported `Types.swift`, `Server.swift` and `Client.swift` as dangling. `WALKTHROUGH.md` references all three correctly and none is in the repository, because the build plugin emits them into `.build/plugins/outputs/`, which any sweep excludes. | #39 | [`API-COVERAGE.md`](API-COVERAGE.md) | **The generated `Output` enums are not closed.** Each carries `case undocumented(statusCode: Swift.Int, OpenAPIRuntime.UndocumentedPayload)`, present mainly so the client half can represent a response the spec never declared, but it is the same type the server returns. Nothing here uses it. The spec-first guarantee is therefore narrower than the usual statement of it: an undeclared status cannot be returned **by accident**, which is not the same as impossible. Worth knowing before anyone reads the declared-response count as a proof rather than a measurement. |
| #18 | [#2](https://github.com/sequeiralabs/company-directory/issues/2) | **`departmentId=1` in HTTPie sends a JSON string and returns `500`.** `key=value` is always a string; an integer field needs `key:=value`. Another instance of #2 rather than a new defect, but the first one likely to be hit by someone following the playbook, so the playbook flags it where the command appears. |
